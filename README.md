# PP Solar Energy Engineering Enterprises: website

Marketing website for PP Solar Energy Engineering Enterprises (Digapahandi, Ganjam, Odisha). Frontend only for now.

- [STYLE.md](STYLE.md): design system and UI/UX standards
- [RULES.md](RULES.md): engineering rules (frontend section applies)
- [MEMORY.md](MEMORY.md): decisions, open client questions and known gaps

## Requirements
- Node.js 20+ (tested on 22) and npm 10+

## Run locally
```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

## Build
```bash
npm run build      # type-check, build, then pre-render every page into frontend/dist
npm run preview    # serve the build at http://localhost:4173
```
The build pre-renders each route to static HTML (`dist/about.html`, `dist/services/solar-epc.html`, …) and generates `sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt` and `404.html`. See [SEO](#seo).
To test a GitHub Pages project-site build locally: `BASE_PATH=/<repo-name>/ npm run build`.

## Deploy (GitHub Pages)
1. Push this folder to a GitHub repository with `main` as the default branch.
2. In the repository, open **Settings → Pages** and set **Source** to **GitHub Actions**.
3. Every push to `main` runs [.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml): install, `npm audit`, build, deploy. You can also run it by hand from the **Actions** tab.

The site is published at **https://ppsolarenergy.in** (custom domain set under Settings → Pages), so it is built with base path `/`. To publish at `https://<user>.github.io/<repo>/` instead, add a repository variable `SITE_BASE_PATH` = `/<repo>/`. Every page is a real HTML file, so links such as `/services/solar-epc` return HTTP 200; unknown URLs get `404.html`.

## SEO

### Built into the site
| What | Where |
|---|---|
| Static HTML for every page (content visible to Google and to AI crawlers that do not run JavaScript) | `src/entry-server.tsx`, `scripts/prerender.mjs` |
| Unique title, description, canonical URL, Open Graph and Twitter tags per page | `src/seo/pageSeo.ts`, `src/seo/headTags.ts` |
| Structured data (JSON-LD): LocalBusiness, WebSite, WebPage, BreadcrumbList, Service, ItemList, FAQPage | `src/seo/structuredData.ts` |
| `sitemap.xml` with image entries, `robots.txt` that welcomes search and AI crawlers | `src/seo/crawlerFiles.ts` |
| `llms.txt` (short summary + links) and `llms-full.txt` (all content) for AI assistants | `src/seo/crawlerFiles.ts` |
| Share image (`og-image.jpg`), app icons, web manifest | `public/`, generated by `npm run images` |
| Fast loading: hero image preloaded, WebP images, code splitting | — |

To change a page's title or description, edit `src/seo/pageSeo.ts`. New services in `src/lib/services.ts` automatically get a page, sitemap entry, structured data and an `llms.txt` line.

### Off-site steps (need the client's accounts)
Most of local ranking happens outside the website:
1. **Google Business Profile** (business.google.com): create or claim "PP Solar Energy Engineering Enterprises" with the same name, address and phone as the site (category: *Solar energy contractor*, plus *Electrician*). Add photos, services and opening hours, and ask every happy customer for a review. This is the single biggest factor for "solar near me" searches and the map results.
2. **Google Search Console** (search.google.com/search-console): add the domain `ppsolarenergy.in` (verify with a DNS TXT record in GoDaddy), submit `https://ppsolarenergy.in/sitemap.xml`, and use *URL inspection → Request indexing* for the home page.
3. **Bing Webmaster Tools** (bing.com/webmasters): import from Search Console and submit the sitemap. Bing's index also feeds ChatGPT search and Microsoft Copilot.
4. **Local listings** with the exact same name, address and phone: Justdial, IndiaMART, Sulekha, and the solar vendor directories the client qualifies for.
5. **Content:** real project write-ups (location, kW, photos) and customer testimonials help most. Send them and they will be added to the site.

## Images
Client photos live in `assets-source/` (originals, renamed). To regenerate the web images after adding or changing a photo:
```bash
cd frontend
npm run images
```
Then register the photo in `src/lib/images.ts`. Never use government, scheme or politician images.

## Project structure
```
assets-source/          original client photos and the profile card
frontend/
  scripts/              image pipeline, pre-renderer
  src/
    entry-server.tsx    build-time renderer (static HTML + crawler files)
    routes.tsx          route table shared by browser and pre-renderer
    seo/                page metadata, structured data, sitemap/robots/llms.txt
    assets/images/      generated WebP (do not edit by hand)
    components/
      ui/               Button, Section, PageHeader, form fields, Picture
      layout/           header, footer, floating contact, site layout
      sections/         shared page sections (process, FAQ, CTA, …)
      home/             home-page sections
    features/           contact form, savings calculator, project gallery
    hooks/              theme, hydration state
    lib/                company facts, routes, services, projects, schemas, formatting
    pages/              one lazy-loaded component per route
    styles/index.css    design tokens (light + dark)
```

Company facts (phones, email, GSTIN, address) are edited in `frontend/src/lib/siteConfig.ts` only.
